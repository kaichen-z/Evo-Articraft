# 待负责人确认的规范问题 (B11–B14)

实现已按规范原文完成, 未私自放宽任何阈值。下列问题解决前,
所有结果的 `provisional_params` 字段会列出它依赖的未定参数。

## ⚠ 最高优先级: 219 条人工标注上的校准结果

完整证据与复现材料见 `calibration/README.md`。这一节的结论改变了下面若干条
问题的优先级, 所以放在最前面。

**四条指标在 219 条人工标注案例上判别力约等于零。**

| | 不满足 | 满足 | AUC (0.5=纯噪声) | τ=0.70 平衡准确率 |
|---|---|---|---|---|
| B11 | 11 | 186 | 0.566 | 0.503 |
| B12 | 92 | 126 | **0.490** | 0.508 |
| B13 | 41 | 177 | 0.552 | 0.575 |
| B14 | 3 | 86 | 未评估 | — |

已逐层排除: 不是阈值问题(最优 τ 只到 0.527)、不是公式问题(原始测量本身
AUC 0.44–0.52)、不是估计量不敏感(换一整族更贴"悬浮/脱离"的估计量, 最强信号
仅 0.089 且方向相反)、也不是标签本身没意义(B12 与 5 星评分 AUC 0.506, 92 个
失败案例里 88 个仍是 5 星)。

**由此产生的三条新问题:**

A. **`S_clearance` 当前定义会毁掉整条 B12**。它两组中位数都是 0, 而它是乘性
   因子 —— 63%/66% 的 B12 分数被它直接清零。这使第 17 条从"定义不明"升级为
   "必须重定义或删除"。

B. **指标覆盖与真实失败分布严重错配**。219 条里的失败计数:

   ```
   B12 实体连接支撑        92
   初始状态穿插/悬浮/脱离    53   <- 无任何指标覆盖
   B13 运动穿模干涉        41
   必要结构是否完整         26   <- 无指标覆盖
   B11 运动范围            12
   B14 多部件耦合            3
   ```

   B11 与 B14 合计对应 15 条失败却占四条指标的一半; 第二大失败模式没有指标。
   → 是否应把资源重新分配到"初始状态装配正确性"上?

C. **人判的"可信实体连接"可能不是几何间隙能表达的量**。唯一有信号的方向是
   "关节邻域有没有专门的连接硬件"(`small_near_50`: 不满足中位 2 个小几何,
   满足中位 5.25 个; AUC 0.356, |信号| 0.144), 而这不在规范的七个乘性因子里。
   → 这算 B12 的实现细节, 还是一条新指标?

**重要局限**: 上述结果使用的契约是从资产自身合成的(关节限位 → expected_range,
每个已声明关节 → 一个 expected_interface), 不是从 prompt 解析的。因此"该有的
关节根本没声明"这类失败, 验证器结构上看不见。这可能压低了全部四条指标的表现,
但无法解释 B12 在**已声明关节**上也毫无判别力。其余局限见
`calibration/README.md` 第 5 节。

## 阻塞级 (不解决则结果不可复现)

1. **q_ref(t) 未冻结**。§06 冻结了 dt / 2s / 3s / 1s, 但没有冻结轨迹形状
   (斜坡? 梯形? min-jerk?)、目标速度、以及默认执行器的控制模式与增益。
   B11 的 `T = exp(-RMSE/0.05Δq)` 和 `L = exp(-overshoot/0.02Δq)`
   完全由这三项决定 —— 同一份资产换个 PD 增益就能从 T=0.55 变成 T=0.95。
   当前占位: trapezoid / accel_frac=0.2 / position 控制 / kp=0.1 / kd=1.0。

2. **接触模型参数未冻结**。B13 的 `S_dyn` 归一化尺度是 0.002·D,
   对接触刚度极度敏感。不同引擎(PhysX 刚性接触 vs MuJoCo soft contact)
   或同一引擎改一个参数, 就能翻转通过/失败判定。
   §06 冻结了时间步却没冻结接触参数, 后者对 B12/B13 的影响可能更大。

3. **仿真器实现未指定**。§01 同时列了 URDF 与 MJCF, §06 只给行为参数。
   若确认 Isaac Sim: (a) 具体版本? 它锁 Python 版本 (4.X→3.10, 5.X→3.11);
   (b) 本地无 RTX 的成员怎么跑? (c) PhysX 在 GPU 上不保证严格确定性,
   但 §06 要求三次试验取最低分且可复现 —— 是否需要固定种子或改 CPU 求解器?

## 一致性问题

7. **§09 的 JSON 示例与 §04 的置信度公式矛盾**。示例给 A3:
   score=0.675, τ=0.70, coverage=full, confidence=0.88。
   但按 `confidence = q_tool·q_contract·q_physics·min(1, |score−τ|/0.20)`,
   应为 `min(1, 0.025/0.20) = 0.125`。以哪个为准?

8. **τ 统一 0.70 在不同结构的公式上严格度差一个量级**。
   指数乘积下, n 个因子要让乘积过 0.70, 每个因子平均需 ≥ 0.70^(1/n):

   | 指标 | 因子数 | 等价单因子阈值 |
   |---|---|---|
   | B11 | 4 | 0.915 |
   | B13 | 4 | 0.915 |
   | B12 | 7–8 | 0.950–0.956 |

   B12 代回 `exp(-g₀/0.02L) ≥ 0.956` 即 `g₀ ≤ 0.0009·L_j`, 几乎零间隙;
   再叠加三次鲁棒性试验取最低分, B12 近乎不可能通过。
   是设计意图还是待校准? (实现未放宽阈值, 但把等价阈值写进了
   `diagnostics.equivalent_factor_threshold`, 使问题可见。)

9. **§04 列了五档覆盖程度, 但 §06 要求工具故障返回独立的 `tool_failure`**,
   两处未统一。实现暂时把 `tool-failure` 作为第六档。

10. **指标之间不独立, Score_full 对同一根因重复计价**。
    柜子案例正好演示: "没有合页"压低 B12; "抽屉被侧板挡住"同时压低 B11 和 B13;
    轴线错了还会连带 B10。37.4 分里包含了对同一物理缺陷的多次计价。
    `repair_queue` 已去重(3 条), 但分数侧没有对应机制。
    建议报告中同时给出"独立根因数"。

11. **32 步扫掠对薄板有隧穿风险**, B13 的 `P_j` 会漏检。
    是否需要连续碰撞检测或自适应细分作为回退? 当前占位: 开启自适应细分。

## 实现中已做的暂定判断 (需追认)

以下三处规范没写死, 实现按"宁可弃权也不误判通过"取了默认, 每一处都能在
`consts.py` 改回去, 公式不动。

13. **`g₀ < 0` (零件互相嵌入) 怎么算**。规范把 `g₀` 定义成"间隙", 没定义
    负值; 而 `getClosestPoints` 对穿透返回负距离, `exp(-max(0,g₀)/s)` 会给
    穿透 **1.0 满分** —— 比缝隙过大更严重的装配缺陷反而不计罚。
    当前占位 `b12_g0_penetration_mode = "abs"`: 嵌入 d 米与缝隙 d 米同等计罚。
    改成 `"clip"` 即恢复规范字面行为。穿透深度写进
    `evidence.interface_penetration_m`。
    → 铰链类接口本来就有互锁重叠, 是否该对特定 `type` 豁免?

14. **部分覆盖能不能判 PASS**。缺失因子实际被当成 1.0, 所以 partial 下的
    分数是完整分数的**上界**。实现据此:上界 < τ 判 FAIL (可证),
    上界 ≥ τ 改判 ABSTAIN, 并标 `diagnostics.score_is_upper_bound`。
    此前 "只跑几何扫掠、没碰仿真器" 的资产能拿到 PASS。
    → 规范未规定, 是否认可这个上界语义?

15. **仿真器报告的 `t_act` 与冻结值不符时怎么办**。`ACTUATE_S = 3.0` 是 §06
    冻结量, 但归一化基准以前从 signals 取, 信号方改一个数就能让 B13 从
    0.0117 变 0.0816。现在只认 `consts`, 不一致时记
    `diagnostics.protocol_deviation`, 不改分数。
    → 报了不同时长 = 没按 §06 协议跑、结果不可比, 是否该直接判 tool-failure?

## 接上 MuJoCo 后, 在真实资产上暴露的问题

仿真器已定为 MuJoCo。第 3 条可以结了 —— 不锁 Python 版本、不需要 RTX、
CPU 求解器给定模型和初态是确定性的, 所以"三次试验取最低分且可复现"不再
需要固定种子。下面是在 31 个 `compile_level=full` 的缓存资产上跑出来的新问题。

16. **`d_anchor` 的估计方式让 B12 全线归零**。规范只说"关节原点到接口几何
    中心的距离", 没说接口几何中心怎么定。当前取活动连杆与父连杆最近接近点的
    中点。实测在四个资产上得到 0.35–0.70 m, 代进 `exp(-d_anchor/(0.05D))`
    得到 f_anchor = 0.0015–0.0034, S_interface 直接归零。
    原因: 铰链类接口的最近接近点可能落在整条贴合边的任意位置, 离铰链轴很远。
    → 是否应改成"接口接触区域的质心"、或对铰链改测"到关节轴线的距离"?

17. **`S_clearance` 的暂定定义过严**。当前取活动连杆到第三方几何的最小净空,
    按 `0.02*L_j` 归一。实测健身凳与面包机都得 0.0 —— 只要碰到任何第三个零件
    就归零, 而"碰到"在装配体里是常态。
    → 净空该按什么归一? 还是应该只看运动走廊内的净空?

18. **MuJoCo 对 mesh 碰撞体做凸包化, 空心资产会出现假穿透**。面包机的
    `p_dyn = 0.138 m`, 是盖子穿进机身 —— 但机身是空心的, 凸包填实之后盖子
    当然"穿透"。B13 的 `S_dyn` 因此为 0。
    → 需要凸分解 (如 V-HACD) 还是接受这个系统性偏差? 影响 P_j 与 p_dyn 两项。

19. **`g0 < 0` 里混着设计性重叠**。健身凳靠背垫嵌在框架里 83 mm, 是正常装配;
    当前 `b12_g0_penetration_mode="abs"` 会按 83mm 缝隙同等计罚, f_g0 = 0.097。
    → 第 13 条问的"铰链互锁是否豁免"在这里变成了具体数字。

20. **协议没规定非目标关节怎么处理**。放任自由时, 42 键的键盘在重力下整体
    崩塌, 测到的是自由摆动 (rmse 2.64 rad) 而不是目标关节。当前占位: 用同一套
    PD 保持初始位姿 (`other_joints_policy="hold"`)。

21. **`I_unexpected` 的"非预期"需要基线**。静置后本就存在的自重支撑接触显然
    是预期的 —— 不排除的话, 36 kg 资产静置 6 s 的支撑冲量就有 2119 N·s, 而
    基准 `0.10*mgT` 只有 106, `S_contact` 恒为 0。当前占位: 静置结束时已存在的
    接触对并入白名单。即便如此健身凳仍有 5134 N·s (靠背扫过框架产生的新接触)。
    → 这类"运动中必然发生的结构性接触"该怎么归类?

22. **执行器增益必须按关节有效惯量定, 不能给绝对值**。`ACTUATOR_KP=0.1 /
    KD=1.0` 是 PyBullet 的无量纲混合系数语义, 在 MuJoCo 不可通约; 而给绝对
    kp/kv 会在跨尺度资产上发散 —— 一个 0.043 kg 的琴键配 kv=50 时
    `m/kv = 0.86 ms << dt = 4.17 ms`, 显式积分必然炸。
    当前改成 `kp = M_jj*omega^2, kv = 2*zeta*omega*M_jj`, omega=20 rad/s。
    → 请确认这个换基, 以及 consts 里那两个 PyBullet 值是否作废。

23. **退化自由度**。键盘旋钮关节 `M_jj = 3.8e-07`, 比模型最大有效惯量小七个
    量级, 任何接触力都能主导它 —— 测到的是数值噪声。当前按 tool-failure 处理
    (阈值 `min_joint_inertia_ratio = 1e-4`)。
    → 这类装饰性关节是该判 tool-failure, 还是该在契约层就排除?
