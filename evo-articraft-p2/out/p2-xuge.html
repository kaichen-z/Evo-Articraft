一、准备工作

按 P0/P1 的格式自动起草了替身契约与绑定

由于现在暂时还得不到P0的文本，所以我们按照P0和P1的要求，分析了20个案例的prompt和其他文件，暂时生成了替代claim

Claim内容：（每条声明都带 source 字段注明来历，存于 specs/<rid>.json，我大致验证过，没有什么问题）：

  • global_form ← 案例类别名（GF1 文本）；part_geometry ← 零件命名（GF2 文本）。
  • part_relations ← URDF 关节拓扑：文件里声明了"抽屉与柜身之间有滑轨"，即得一条可验证的 drawer attached_to body；再加命名启发（名字含 drawer → inside，含 lid → above）。声明是作者意图、验证用实际几何，两个通道独立，不构成自证。
  • proportion_claims ← 命名对称组：wheel_0…wheel_4 理应一样大（target_ratio=1，tolerance=0.10）。预期值来自命名约定而非实测，同样避免循环。
  • 部件引用一律经绑定层解析（实例名 → 抽象 part 展开全部实例 → geom 名兜底）。

选了 20 个案例，按机构类型配齐而非随机抽

从 110 个训练案例按关键词配 20 个槽位——棱柱抽拉类 4（抽屉柜、伸缩臂、台钳、收银机）、旋转开合类 6（园门、电柜门、垃圾桶盖、翻盖手机、眼镜、帕尼尼机）、连续转子类 4（塔扇、风力机、转盘、水轮）、链式 2（三自由度腕、指骨链）、混合家电 4（办公椅、显示器支架、洗碗机、打印机）。

二、GF1-GF4的实现

GF1

整体形态对齐

冻结渲染协议：统一中性灰材质、方位角 0/90/180/270、仰角 −20°、相机距离 1.7×AABB 对角线、分割通道把背景抠成浅灰。编码器冻结为 open_clip ViT-B-32 / laion2b_s34b_b79k，四视角图文余弦取均值。

补充：我们加了 20 类干扰项 softmax——每个资产的照片在全部 20 个类别文本里去匹配，得到匹配的概率以及在20个案例里面的排名；另附最差视角 min_cos，防止单面坍塌被均值抹平。
发现的问题（渲染管线，影响 GF1-GF4 全部四项）：这批 URDF 资产只有 visual 网格、没有 collision 网格（实测 <collision> 标签 0 个，<visual> 标签 69 个），而 MuJoCo 编译 URDF 时默认只保留 collision、丢弃 visual——所以整个模型编译出来是空的（ngeom=0），渲染出来是一张纯灰色空白图，CLIP 是在瞎猜一张什么都没有的图片。

修法是在 mj_scene.py 注入的 compiler 标签里加一个 discardvisual="false"： 
inject = (f'<mujoco><compiler fusestatic="false" meshdir="{meshdir}" '
          f'discardvisual="false"/></mujoco>')
这个改动是安全的——如果资产本来就有 collision 网格，这个开关不会改变任何行为，只是多保留一份 visual 网格；只有对"只有 visual、没 collision"这种资产才会真正生效。修完之后，办公椅（rec_office_chair_0004）的 69 个 geom、7 个零件全部正确渲染出来了。

需要确认：这个 bug 是在本地重新加载这批资产时触发的，不确定原始 20 条结果跑的时候，本地 URDF 缓存是否也缺 collision 网格——如果是，20 条结果里可能有一部分案例的渲染实际上是空白图，分数不可信，需要重新跑一遍验证。
新增：三视图判形状。这是一项独立于 GF1/GF2（4方位角环绕）的新检查——正视图（elev=0, az=0）、侧视图（elev=0, az=90）、俯视图（elev=89.9, az=0）三个固定工程制图角度，取三张图的平均特征，对一份粗粒度品类词表（cabinet/fan/chair/lamp/door/machine-housing/turbine/hvac/cutting-tool/wheeled-vehicle/linkage/handheld，共12类）做 zero-shot 分类，输出 top-3 猜测。已在办公椅（rec_office_chair_0004）上验证：正确判为 chair，置信度 99.07%（次优 lamp/light 仅 0.70%）。用途：给"这个物体整体形状对不对"提供一个和 GF1 裸余弦独立的交叉检查信号。代码在 p2/render.py::three_orthographic_views + p2/dictionary.py::classify_shape_from_views。
GF2

部件及几何对齐

逐零件隔离渲染：其余 geom 移入隐藏组、相机按该零件自身 AABB 重新构图，同样四视角；按规格先聚合视角、再对零件宏平均。零件文本来自 part_geometry 的形状描述。

补充：兄弟部件辨识——每张零件照片在本资产全部零件文本里做选择题，报告认对概率与实际最像谁（best_match），用于诊断"零件做得不像自己"；无几何、AABB 退化、被引擎融合的中间零件记不可测，不计入宏平均。
新增：prob_vs_sibling_parts 除以瞎猜基线 1/N，得到 prob_vs_chance。零件数 N 不同的物体，同样的原始概率含金量不一样——拿现成的 results.json 重新算了一遍，排序会反过来：

新增：跨物体零件 dictionary（p2/dictionary.py）。兄弟辨识测的是"这张照片像不像本资产的其他零件"，测不出"这个零件根本不像它这一类该有的样子"——尤其是零件少、没有兄弟可比的物体完全用不上。这里另建一份和具体资产无关的候选池：18 类常见零件文字描述（housing/body、base、arm、lid、door/panel、ring、dial、button/knob、jaw、bracket、wheel、drawer、handle、post/tube、frame、cap/cover、hinge/bearing、axle）。其中 16 类来自 A1-6 for yiyun/data/contracts-300/ 里 expected_parts 名字的真实词频统计（98 份 contract，合并了单复数和近义词）；另外 2 类（hinge/bearing、axle）词频排不进前列，是照你最早举的"轴承"例子手动加的；词频表里另外几个高频词（carriage、head、barrel、plate、keys、flap）判断跟已有类别形状区分度不够，没有单独列出来，是我自己取舍的，不是全自动生成。跑法和 GF2 现有 softmax 代码完全复用，只是候选池从"本资产零件"换成这份固定词表。

已在办公椅上验证：base、wheel_1–wheel_4 全部判对，唯独 wheel_0 被判成 button/knob（47.8%），"wheel"甚至没进它的 top-3——五个轮子理应长得差不多，这个不一致是自动测出来的、值得人工去看一眼这个具体轮子的疑点。文本 v1 是占位符，正式版可以换成从真实渲染图平均出来的图像原型（build_image_prototypes 已经预留了接口）。
试过、又改回来的一个方案：dictionary 曾经改用正/侧/俯三视图渲染（而不是复用 GF2 已有的 4 方位角渲染），本意是让 dictionary 和"三视图判形状"用同一套拍摄方式。实测效果更差，已改回 4 方位角：换成三视图后，5 个轮子里 0 个判对 wheel（含原来判对的 wheel_1–4，全部变成 button/knob）。原因是轮子这类轴对称零件，如果它装配后转轴方向刚好正对着"正视图"或"侧视图"这两个固定的世界坐标方向，拍出来就是一个圆柱截面（看着像纽扣），而不是能看出"这是个轮子"的滚动面；4 方位角因为角度多、又是斜着拍的，被这种"角度凑巧对齐"坑到的概率小得多。三视图仍然保留用于整体形状判断（这个尺度上没有遇到同样的轴对称问题，效果很好）和网页展示用的缩略图，只是不再用于零件 dictionary 的打分。

过程中还顺手抓到一个变量名重复导致的 bug（循环里 shape_views 变量名和外层整体三视图变量重名，把返回值污染成了最后一个零件的照片）——已修复，不影响当前代码，记录下来是因为它一度让"整体三视图判断"的结果在两次运行之间完全不一致（99% chair vs 46% door/hatch），排查过程说明这类"看起来像模型不稳定"的问题，值得先怀疑变量名/数据流之类的低级错误，而不是先怀疑模型本身。
GF3

部件关系保真度

目前得到四种部件关系（容差一律按整体对角线 D 归一化）：attached_to = 两零件所有 geom 对的最小符号距离，sd<−0.005D 判穿透、≤0.01D 判接触（唯一算满足）、其余判分离；inside = A 的 AABB 体积落入 B 的比例 ≥0.7；above = z 向间隙 ≥−0.05D 且水平投影重叠 ≥0.3；aligned = 偏轴中心偏移 ≤0.05D。声明指向抽象部件时展开为全部实例、须全部满足。

补充：output对应到相应的零件（哪两个零件、实测几米）；引用解析失败或零件无几何记 unmeasurable
GF4

比例保真度

尺寸从 q0 世界系 AABB 提取：height=Z 边、length=水平长边、width=水平短边、area=投影面积、volume=AABB 体积。成组声明（[1,1,1]）展开为对第一成员的逐对比较；按规格公式 exp(−|log(r_obs/r_target)|/σ) 打分。

补充：P0 声明的是 tolerance、公式要的是 σ，两者换算规格未定，我们暂用 σ=ln(1+tolerance)（恰好使"偏到容差边界"得分 = 1/e≈0.37）；measure 的几何定义也是暂定约定。这两个问题我都放到了页面最下方的问题清单。
